DEMO ONLYThe WX-84 server runs on a laptop. Agents' browsers cannot reach localhost, and Chrome will not let Genesys Cloud embed it, so a Cloudflare quick tunnel lends the laptop a temporary public HTTPS address. It carries only requests from the agent's browser to WX-84, and its URL changes on every start.

    Three checks before an agent gets in

    WX-84 does not trust what the browser says. It asks Genesys Cloud about the token itself, and all three answers must fit.

    ORGANIZATION Is this token from our Genesys org? users/me returns the organization id, which must equal the org pinned in WX-84's config.
    FAILS403 · different organization
    STOPSAgents from another company's Genesys org.
    APP Was this token issued to WX-84? tokens/me names the OAuth client, which must be WX-84 Agent Console (PKCE).
    FAILS403 · not issued to WX-84
    STOPSA token lifted from another app in the same org.
    PERSON Does WX-84 know this agent? The verified e-mail must match exactly one line in users.txt.
    FAILS403 · ACCESS DENIED
    STOPSGenesys users without a WX-84 account, and duplicate entries.

    Two permission systems, one identity

    GENESYS CLOUD DECIDES

    • Which agent gets the chat (one queue, any member of the group WX-84 Agents)
    • Who sees the WX-84 widget (group WX-84 Agents, WX-84 Weather Desk queue only)
    • Who may read the conversation and the customer's last name (the agent's own roles; WX-84 reads it with the agent's token)

    WX-84 DECIDES

    • Which weather stations an agent sees (users.txt, read on every request, filtered on the server; the rest stay hidden)
    • Who may change permissions (role admin, through the maintenance panel)
    • What is logged (every grant, denial and change in the flight recorder; never the customer's name)

    The only thing WX-84 takes from Genesys to decide access: the verified e-mail address.

A production build would add a shared session store and a server-side exchange with refresh tokens.

    What setup.js creates in Genesys Cloud
