How a partner app knows which agent is looking

The partner app never sees the agent's password. Genesys Cloud gives the agent a time-limited pass for that one app. The partner app asks Genesys whose pass it is, then checks its own list to decide what to show.

    Building the same into your own app

    WX-84 is one example. Any partner app inside Genesys Cloud has the same two jobs: find out reliably which agent is looking, then map that agent to its own users and permissions.

    Job 1: find out who the agent is

    RECOMMENDED · WHAT WX-84 DOES

    Sign in with Genesys Cloud

    OAuth Authorization Code with PKCE in the agent's browser, then verify the pass on your server with users/me and tokens/me.

    Works for every Genesys customer without extra work for their IT department. The agent signs in once, to Genesys.

    ALTERNATIVE

    The customer's own single sign-on

    If your app already signs users in through the customer's identity provider (Microsoft Entra ID, Okta, Ping), the agent is recognized there. Genesys and your app trust the same source.

    Needs the customer's IT to register your app. Map by the corporate e-mail or employee ID.

    AVOID

    Anything the browser simply claims

    The agent's name in the widget URL, one shared login for all agents, or a single technical account for your app.

    A URL can be edited by anyone. A technical account (Client Credentials) proves which app is calling, never which agent is looking.

    Job 2: map the agent to your permissions

    WX-84 DEMO

    By e-mail address

    Your list holds the agent's Genesys e-mail. Simple to read and to explain.

    E-mail addresses can change or be reused. Exactly one match, otherwise deny.

    PRODUCTION

    By Genesys user ID

    Your list holds the permanent ID Genesys gives every user. It never changes, even when the e-mail does.

    Store the ID at first sign-in or when an admin links the user.

    AT SCALE

    By Genesys group or role

    No list of people: "everyone in group Billing Tier 2 may see billing data". Your app reads the agent's groups with the same pass.

    Needs one more read-only scope. Leavers lose access as soon as Genesys removes them from the group.

    What a partner needs, per customer org

    1. An OAuth client with grant type Code (PKCE) and only read-only scopes.
    2. An Interaction Widget that shows your app next to the interaction, limited to the right group and queues.
    3. On your server: verify every new pass with Genesys, pin the customer's organization ID, and check the pass was issued to your OAuth client.
    4. Your own user list or policy, checked on every request, with every decision logged.

    Questions partners and executives ask

    Does the partner app ever see the agent's password?

    No. The password only goes to Genesys Cloud, or to the company's own sign-in behind it. The partner gets a time-limited pass and nothing else.

    Does the agent have to sign in twice?

    No. The agent is already signed in to Genesys, so the pass is issued without a login page. Some browsers (Safari, private windows) block that hidden step; then the agent clicks once and a small window flashes.

    What can the partner do with the pass?

    Only what its scopes allow, never more than the agent may do, and only for one hour. In WX-84: read the agent's profile and read the conversations this agent can see. Nothing can be changed.

    An agent leaves the company. What happens?

    Genesys disables the account, so no new pass is issued. A pass already issued expires within the hour. The partner's own list should be cleaned too; mapping by Genesys group makes that automatic.

    Who decides what the agent sees in the partner app?

    The partner, with its own list or policy. Genesys only vouches for who the agent is. Customer data read from Genesys stays under Genesys's rules, because the partner reads it with the agent's own pass.

    Which personal data does the partner process?

    The agent's name, e-mail and Genesys user ID, plus whatever customer data it reads with the pass. WX-84 shows the customer's last name but does not store or log it.

    Why not just put the agent's name in the widget URL?

    Anyone can edit a URL and type someone else's name. A pass issued by Genesys and checked by the partner's server cannot be invented.

    Could the agent desktop or another app read the secret stub?

    No. The browser keeps each website's storage apart. Only the WX-84 page that created the stub can read it, and it deletes the stub right after use. PKCE does not help if the partner's own page is compromised, so partners must protect their page, for example with a strict Content Security Policy.
